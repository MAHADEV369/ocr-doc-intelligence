# DocIntel Chat — LLM chat with grounded extraction

Three ways to use the extraction corpus with an LLM:

1. **Web chat** at `http://localhost:8001` (upload PDFs, ask questions, click citations).
2. **MCP server** for Claude Desktop / any MCP-capable chat client.
3. **CLI chat** in the terminal.

All three use the same retrieval + fact layer. Numeric answers are served from
the extracted field table, not generated by the model. Qualitative answers use
the local LLM with retrieved pages, and every 3+ digit number in the answer is
checked against the supplied evidence before display.

## 1. Web chat

```bash
uvicorn src.chat_app:app --port 8001
# open http://localhost:8001
```

- Sidebar: 30 documents / 4,709 pages indexed; filter to one document.
- Upload a PDF: runs the hybrid extractor (PyMuPDF → Docling → PaddleOCR) and
  adds it to the index.
- Numeric questions return `mode=structured_facts` with exact values and page
  citations. Qualitative questions return `mode=llm`.
- Click a citation chip to read the source page.

Local LLM defaults:

```bash
export OLLAMA_URL=http://localhost:11434
export DOCINTEL_LLM_MODEL=qwen3.5:9b
```

Any OpenAI-compatible endpoint can be substituted by changing `llm_call` in
`src/rag.py`; no paid API is required.

## 2. MCP server (Claude Desktop, Cursor, any MCP client)

```bash
python -m src.mcp_server
```

Example `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "docintel": {
      "command": "/opt/anaconda3/bin/python",
      "args": ["-m", "src.mcp_server"],
      "cwd": "/Users/trident/Desktop/ocr"
    }
  }
}
```

Tools exposed:

| Tool | Purpose |
|---|---|
| `list_documents` | ids, companies, types, page counts |
| `search_documents` | FTS over page text and tables with citations |
| `get_financials` | exact value/unit/period/basis/page/status |
| `get_page` | full text + tables for verification |
| `ask_documents` | grounded answer + citations |
| `extract_pdf` | run hybrid extraction on a local PDF and index it |

The chat host decides when to call `get_financials` vs `search_documents`; the
tool descriptions explicitly tell it not to invent numbers.

## 3. CLI

```bash
python -m src.chat_cli --list
python -m src.chat_cli
python -m src.chat_cli --doc reliance_annual_report
```

## OpenAI function-calling schema

`tools/openai_tools.json` contains the same tools in OpenAI `tools` format. Send
it with the chat completion request and execute the calls against the HTTP API
(`/api/chat`, `/api/documents`, `/api/document/...`) or import `docstore`/`rag`
directly.

## Quality controls

- **Structured-first:** field questions bypass the LLM and return exact values.
- **Citation enforcement:** system prompt + deterministic formatter use
  `[Company p.N]`.
- **Number guard:** if the LLM emits a 3+ digit number absent from the evidence,
  the deterministic answer replaces it.
- **Period handling:** FY2025-26 maps to “year ended 31 Mar 2026”; Q2 questions
  select the Q2 FY2026-27 fields.
- **Basis labels:** consolidated vs standalone is shown for every field.
- **Missing values:** `null` is never rendered as zero.

## Benchmarks

- Corpus: 30 documents, 4,709 pages, 411 structured fields.
- Hybrid extractor on image-only statements: numeric F1 **1.00** on the three
  pages tested; table-cell recall **1.00** where a native gold table exists.
- Numeric chat answers are deterministic, so their accuracy is the extraction
  accuracy of the cited field.
